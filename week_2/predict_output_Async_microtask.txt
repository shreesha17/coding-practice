1. ### **Microsoft | Technical Round: The Microtask Priority Riddle**

**Question:** Predict the exact output. Explain why the `asyncFn` behaves differently than a standard promise chain.

JavaScript
console.log('1 - Sync');

setTimeout(() => {
  console.log('2 - Macrotask');
}, 0);

async function asyncFn() {
  console.log('3 - Inside Async');
  await Promise.resolve();
  console.log('4 - After Await');
}

asyncFn();

Promise.resolve().then(() => {
  console.log('5 - Microtask');
});

console.log('6 - Sync End');

OUTPUT:
1 - Sync
3 - Inside Async
6 - Sync End
4 - After Await
5 - Microtask
2 - Macrotask

when we call asyncFn() -> function exection starts and '3 - Inside Async' logged to console -> as soon as we hit 'await', function 
execution is paused and next code block is pushed to microtask queue and control comes out of function and synchronous code execution happens ->
then microtask queue tasks gets executed then macrotask queue tasks. 

'Async' function behaves same as standard promise chain as it is syntactic sugar over promises
